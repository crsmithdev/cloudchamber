## The cost, measured

The successful draft alone, from the CLI's own usage on every step, at
list price:

| model | stage | calls | output tokens | of which thinking | cost |
|---|---|---|---|---|---|
| Opus 5 | schedule | 1 | 3.7k | 0 | $0.19 |
| Opus 5 | scene | 22 | 27.4k | 0 | $5.63 |
| Sonnet 5 | screen-ledger | 30 | 118.8k | **102.5k** | $2.00 |
| Sonnet 5 | screen-structure | 30 | 30.2k | 16.8k | $0.66 |
| | | **83** | | | **$8.48** |

The whole chain, both failures and the aborted first draft included: 152
calls, $16.68 at list, 2 h 14 min on the clock. Opus 48 calls $9.91;
Sonnet 104 calls $6.78, with 351k of its 428k output tokens spent
thinking.

**Sonnet is not cheaper here.** It thinks about five times as long per
call as Opus on the same screens, and the screens are output-bound: the
input is almost entirely served from cache on both models (Opus read
397k and wrote 790k cached tokens against 96 uncached). Thirty ledger
screens on Sonnet cost $2.00; the same thirty on Opus, priced from run
7's character counts, come to about the same. What Sonnet saved on the
per-token rate it spent on thinking tokens.

Two more costs the figures do not carry: two shape failures that stopped
the draw, and a draft that reached 13 beats where run 8 reached 12.

| chronology | one night, linear | nine days, a flashback, a 393 strand |

The judgement stages ran on Sonnet: the same delivery questions passed
and the register rewrites fired. But the ledger screen found **9 flags
where run 8's found 37** on a draft of the same length, and the shape
of the prose did not change. Either Opus over-flags or Sonnet under-finds,
and the 28 restated flags Opus raised on run 8 against 38 here say the
deterministic screens saw the same kind of draft. That is the second
reason not to move the screens. The
draft's losses are in the story's shape, which Opus chose. One run cannot
separate that from the model of the screens; two can, and it is not worth
two when the cost is the same.

## Verdict

**Keep the judgement stages on Opus 5.** Sonnet 5 costs the same on
these stages because it thinks five times as long, it produced two shape
failures in one run that Opus never has, and the one draft under it
scored a point lower on a panel of five. `--models` did what it was built
for: one flag, one run, one answer.

## Follow-ups

1. **A time signpost the screen can check.** Clarity losses name the
   timeline every time. A deterministic check that a beat whose day or
   hour differs from the last beat's opens with the change would catch
   it without a call.
2. **Thinking is most of the output cost.** The CLI does not expose an
   effort setting on a headless call; if it did, the screens at low
   effort are the obvious saving to try before another model.
3. The one-speaker question and the restated trigger, from run 8.
4. Beat 9 waits at gate 2 over both ceilings; the three open ledger
   flags with it.
